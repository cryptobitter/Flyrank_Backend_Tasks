Infrastructure Explained

The DNS Walkthrough: Demystifying the Internet's Phonebook

A clear, non-technical explanation of what happens between pressing [Enter] on a URL and receiving your first byte of HTML.

What is DNS, and why does it matter?

Imagine if you had to memorize the 12-digit GPS coordinates of every friend’s house before you could visit them. Computers communicate using numeric IP addresses (like 75.2.60.5). Humans, however, remember names like aditya-rajput-backend.netlify.app. The Domain Name System (DNS) is the global, decentralized translation layer that maps friendly domain names to server IP addresses in under 50 milliseconds.

1

Local Resolver (The Courier)

Your browser first checks its local cache. If missing, it asks your Recursive Resolver (usually your ISP or 1.1.1.1) to find the address.

2

Root Server (.)

The resolver asks the global Root Server: "Where do I find domains ending in .app?" The Root directs it to the .app TLD nameserver.

3

TLD Server (.app)

The TLD server knows who manages netlify.app and responds with Netlify's Authoritative Nameservers.

4

Authoritative Nameserver

Netlify's server holds the final record. It tells the resolver: "Here is the IP address for that site!" The resolver caches it and returns it to your browser.

What is a CNAME Record? (The Alias)

An A Record points directly to a fixed IP address (e.g. aditya.com → 75.2.60.5). A CNAME (Canonical Name) Record points a name to another name (e.g. www.aditya.com → aditya-rajput-backend.netlify.app). This lets modern cloud providers change server IPs, route across multi-region CDNs, and handle load balancing behind the scenes without breaking your custom domain configuration.
